# 用户可见界面视觉验收

状态：implemented

## 决策理由

页面可以在类型检查、单测和产品旅程通过后仍然出现挤压、重叠、导航抖动或对比不足。浏览器交互证明功能结果，几何断言和截图基线捕获已登记的回归；它们都不能完整判断信息层级、美观与合理性，因此交付还需要实现者阅读真实产品画面。

## 取舍与当前契约

视觉验收与源码审查、相关测试同等必要。取画面手段不绑定特定产品；覆盖范围按改动风险选择，修复影响交付的缺陷后复查受影响画面，不规定固定顺序或次数。代表页面的自动截图基线与 Axe 是现有质量门禁的一部分，不替代人工视觉判断。

完整覆盖规则、判定标准、几何断言和证据要求只维护在[开发规范 §5.1](../../06-开发与测试规范.md#51-用户可见界面的视觉验收)。视觉 Token 和设计语言见[设计规范](../../05-桌面UI与动效规范.md)，独立历史缺陷的处理遵循[任务边界](../../06-开发与测试规范.md#2-实现工作流)。

## 验证入口

`apps/web/e2e/product-quality.spec.ts` 包含代表页面截图基线、Axe、布局与主题场景。生产旅程按[检查阶梯](../../06-开发与测试规范.md#6-检查阶梯)执行；完成说明提供实际查看画面与结果，测试日志不作为视觉代签。
