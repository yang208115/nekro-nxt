# 已实施：DSH 0.1.1-rc.2 群聊能力组合

状态：implemented

## 结论

NekroNXT 通过 DSH `0.1.1-rc.2` 公开 Service、Plugin 和 Revision Scope 组合子智能体、网页搜索、Spill 与可靠性能力，不 Fork 或复制 DSH 内核。主智能体保留 Revision 授予的全部工具，系统提示只建议把搜索、历史读取、文件扫描、Shell 和扩展开发等高噪声任务委派出去，不强制路由。高风险能力只在智能体配置界面给出真实警示；一个智能体的多个频道各自拥有独立根 Session 和 descendant tree。

## 精确加载平面

Host 单例加载：

- `dsh-session-projection` → `dsh-subagent` → `dsh-subagent-spawn-in-process`；
- NekroNXT Scope 继承适配层使用 DSH 公开 `bindScopeParent()`，让 rosterless in-process child 加入精确父 Agent Scope；
- `dsh-tool-subagent-report`，只通过官方 `registerContinuableSetup()` 注入 continuable child；
- `dsh-web` → `dsh-web-search-deepseek`，复用 DSH settings/credentials；
- NekroNXT `QuotaLocalSpillStore`（继承公开 `SpillStore`、复用公开 `saveTextFile()`）→ `dsh-spill-policy`；
- `dsh-llm-retry`、`dsh-compaction-tool-result-pruner`、`dsh-tool-call-timeout-policy`。

每个获准 `subagents` 的根 Revision Scope 独立加载 `dsh-tool-subagent-control`、`dsh-tool-subagent-control/list-agents` 和 `dsh-tool-subagent`。模型工具分别是 `send_message/interrupt_agent/list_agents/subagent`；频道发送保持 `send_channel_message`。foreground 与 continuable child 都继承父 Scope 当前真实存在的工具和提示，再通过 child 自己的 deny restriction 移除频道沟通与子智能体协调工具。每个获准 `webSearch` 的根 Scope 独立加载 `dsh-tool-web`，只开放 `web_search`，不开放 `web_fetch`。

## 子智能体边界

- Provider 固定为官方 in-process `spawn`；`backgroundMode=continuable`、`enableRunInBackground=true`、`maxDepth=1`、`agentOptions.maxTokens=4096`；
- child 从父 Revision 继承频道上下文、历史、Asset、网页、文件、Shell、Skill、动态 Cordis、持久 Extension 和后续普通工具，不构成权限扩大。固定拒绝 `send_channel_message`、`finish_channel_turn`、`retract_channel_message`、`nudge_channel_member`、`subagent`、`send_message`、`interrupt_agent`、`list_agents`；可选名称只在父 Scope 真实存在时写入新 descriptor；
- continuable child 每次 fresh/cold Activation 再按当前可见工具补充 deny，防止父 Scope 后来新增频道动作。历史 descriptor 已拒绝的名称在恢复时消失会由 DSH fail-closed 为 `NOT_RESUMABLE`，Host 不改写 DSH 历史，根智能体创建新 child；旧 `allow=[]` descriptor 继续保持无父工具行为；
- 0.1.1-rc.2 continuable descriptor 不持久化 `maxTokens`，因此 Host 通过官方 `registerContinuableSetup()` 在每次 fresh/cold Activation 的 `agent/request` waterfall 重新写入 4096；
- `tools.restrict()` 只用于 child 可见工具组合，不作为进程权限边界。文件/Shell 继续保留每根 Session Scope 的隔离 Service，没有迁移为 Host 全局 Service；
- 根提示保留频道投递和回应义务，并说明何时适合委派；child 看不到频道通信规则，只被告知通过普通最终输出或可见的 `report` 回报。两者继承同一完整人设，spawn child 不复制父对话 transcript；
- 关闭根 Session 前调用 `drainContinuableDescendants()`，等待 descendant child-first 静止后再 dispose 根；同一智能体其他频道根不受影响；
- 按用户确认，本期不自研 child 并发、总运行时长、总轮次、总 Token 或 followup 队列上限，只落实 DSH 官方深度与逐请求 Token 边界。

## 动态创造所有权

- 根 Session 和它的所有直接 foreground/continuable child 可以调用同一个动态 Runner。同根 sibling 共享现有单 Plugin 与 `transition-in-flight` 门禁，不新增队列；提示明确共享 Runner 的修改任务不得并行委派；
- child 的 Cordis Tool Call 和源码只进入 child Session，Runner 在 `list/inspect/define/run/snapshot/stop/undefine/reference` 入口把 owner 规范化为根 Agent。解析同时验证公开 Session Header 的 `origin/parentSession/delegationDepth`、根 Agent 在线身份、Channel、Episode、不可变 Revision、`dynamicCreation` 授权和 `#dynamicSessions` 精确 Runner，不按产品智能体 ID 猜测；
- NekroNXT Host Inspect 使用同一 owner 解析；DSH Client Inspect 不增加产品接线。创造工作台的审批、Client/Host 证据、保存和调用继续使用根 Episode API；
- Plugin、Package、Run 以及持久 Authoring Task/Attempt/Event、自动验证和 continuation 都归根 Episode。自由文本 `report` 与 Authoring continuation 都可能增加根上下文或唤醒下一 Step，这是当前接受的取舍；Host 不新增裁剪、去重或结果 Schema。

## Web、Spill 与可靠性

- DeepSeek Web Provider：`maxTokens=1024`、`maxUses=2`；工具 `searchMaxResults=5`、`searchTimeoutMs=60000`。每次搜索是额外模型请求，能力页显示费用与外部不可信内容提示；
- Provider 可用状态从 `ctx.settings` 和 `ctx.credentials` 投影。未配置凭据时新建智能体默认不开启并引导配置；不建立第二套供应商系统；
- Spill：`maxInlineBytes=50000`，写入 `dsh/spill/`；单 artifact 8 MiB、单 Session 64 MiB、Host 2 GiB。重启扫描已有文件后继续计额，超限拒绝新写入，原工具结果由官方 policy 保留 inline；
- locator 只进入 DSH 内部结果与 Session，不成为 Adapter、Asset 或用户文件身份。关闭文件工具后 artifact 仍可恢复，但智能体不能自行回读；
- 工具结果裁剪使用 8192/4096/1024 字符阈值，Web 等声明 timeout 的工具由官方 timeout policy 协作取消，模型请求按 Provider 声明的 retry policy 恢复。

## 可复现验证

基于已安装 0.1.1-rc.2 发布包的测试证明：根智能体在 child 阻塞时仍可接受下一条频道消息；foreground 与 continuable child 继承父级非沟通工具、完整人设和空对话；continuable child 在 Host 重启后可由官方 `send_message` 冷恢复，fresh/cold 请求均为 `maxTokens=4096`；可选频道动作新增时会被补充拒绝，消失时旧 child fail-closed 后可新建；child 可完成 Host Inspect、两版 Cordis Define/Run/Stop/Inspect，inventory、Authoring 账本和验证证据始终归根 Episode；无授权智能体看不到子智能体工具；同一智能体不同频道根不共享 child；动态扩展无法注入 `agentPresets/subagents/web/spillStore` 等私有 Service；搜索请求固定 1024 tokens/2 uses，结果截断为 5 条，外部指令文本只进入 tool result；Spill locator 可恢复且三层配额拒绝溢出。

## 未来方向与参考取舍

关联方向：长期 Job、远程 Runtime、更多 Web Provider、多设备备份和智能体自开发。

保留接缝：DSH Provider registry、Session projection、`bindScopeParent()`、continuable setup、Revision Scope、抽象 `SpillStore`、settings/credentials 和公开关闭生命周期。没有把供应商、宿主路径或 in-process 实现写入 Core 持久契约，因此没有锁死未来 Process/Remote child 或远程 Spill。

本次明确不提前实现：Workflow、Ralph、web_fetch、社区 Provider、频道级权限策略、自研资源调度器、Spill 清理 UI 和远程 artifact 服务。

参考 DSH 0.1.1-rc.2 base/headless 官方组合与发布包类型；借鉴其 Service 三分、Scope 父链、child-first drain、Provider 选择和 best-effort Spill，拒绝照搬 CLI 全局文件/Shell、复制官方 Cordis Tool、把 `available()` 当凭据就绪、用提示词冒充权限边界或深改上游实现。
