# 微信 iLink 实验通道适配器

状态：implemented

## 结论

NekroNXT 通过 `@nekro-nxt/adapter-wechat-ilink` 接入实验性微信 iLink 私聊通道。Connection 由宿主扫码登录会话创建：用户只扫描二维码并确认，账号 ID、访问令牌、API 地址和 CDN 地址不进入用户可见表单。访问令牌写入 Host-owned Credential；连接详情只暴露入站图片接收开关。

该通道基于非官方 `wechat-ilink-client`。协议稳定性、账号风控和合规风险不由 NekroNXT 保证，建议只使用专用机器人账号。首版不开放群聊、Mention、引用、撤回、主动发送或出站媒体。

## Host 契约

Adapter descriptor 声明 `creation.mode = qr-login`。产品连接向导读取该字段后进入宿主登录会话，不按 `adapterKey` 分叉独立页面。Schema 表单仍是默认创建方式。

宿主拥有登录会话：

- `POST /api/connections/wechat-ilink/login` 开始会话并返回二维码；
- `GET /api/connections/wechat-ilink/login/:loginId` 读取 pending / scanned / confirmed 等状态；
- `DELETE /api/connections/wechat-ilink/login/:loginId` 取消尚未完成的会话。

确认登录后，Host 用登录结果创建 Connection、保存 `botToken` 凭据并挂载 Runtime。`POST /api/connections/:connectionId/wechat-ilink/inbound-media` 只更新已有微信 iLink 连接的入站媒体开关，随后停止并重新挂载 Runtime。

出站只支持已发现私聊的纯文本回复，且必须持有该会话最近的 `context_token`。`context_token` 只作为投递凭据保存在 Connection scoped state，不进入消息 facts、日志或用户可见响应。

## 传输与状态

Runtime 使用长轮询接收私聊。`syncBuf` 与每个私聊用户的 `context_token` 写入 Connection scoped state，重启后继续使用。会话过期后发布认证失败诊断，要求重新扫码登录。

群消息中的 `group_id` 被忽略并记录诊断，不创建群频道。入站媒体默认开启；关闭后图片和文件只记录可解释占位内容，不下载明文。

## 验证

- Adapter 包测试覆盖 descriptor、入站映射、媒体占位、context_token 回复和会话过期；
- Server 组装测试用 Fake login/transport 覆盖扫码创建、入站媒体开关、私聊发现和收发诊断；
- Web 产品测试覆盖扫码弹窗、Host 刷新后登录态保留，以及连接详情中的入站图片开关。

当前实现尚未完成独立真实账号验收。完成真实扫码、私聊文本、入站媒体和会话过期测试后，才能标记为“已验证支持”。

## 未来方向与参考取舍

关联方向：更多聊天平台 Adapter、宿主登录会话协议。

保留接缝：第一方 Adapter 进入 `adapter-builtin-roster`，产品 UI 只消费 descriptor 的 `creation` 字段，Host 拥有登录会话和凭据。明确不把微信 iLink 协议字段暴露给通用 Schema 表单，也不提前建设 OAuth、群聊或出站媒体。
