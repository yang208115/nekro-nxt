# Web 产品旅程交付门禁

状态：implemented

## 决策理由

`renderToStaticMarkup` 和 `MemoryRouter` 的静态测试不能验证 React Effect、真实路由、SSE 或外部 Store 生命周期。项目曾因 Zustand selector 每次产生新数组而出现循环更新和整页白屏，原有单测、API、类型检查与构建未捕获。生产构建下的真实页面旅程因此成为 Web 交付证据。

## 取舍与当前契约

局部 Web 变化验证受影响的用户闭环；共享导航、全局状态和壳层变化扩大到相关路由，CI 与产品交付复核保留完整旅程。页面运行时错误、空白根节点和关键主内容不可见视为失败，API 成功或 Error Boundary 不能代替页面可用。截图基线与 Axe 补充自动化质量检查，真实像素另由视觉验收判断。

验证范围、命令与退出条件只维护在[开发规范 §5–6](../../06-开发与测试规范.md#5-测试设计)，视觉规则见[§5.1](../../06-开发与测试规范.md#51-用户可见界面的视觉验收)。这些要求不以浏览器工具缺失为通过理由，也不要求每个局部修改先完成全产品整改。

## 验证入口与隔离

`playwright.config.ts` 与 `apps/web/e2e/` 拥有生产 Host、页面场景、运行时错误与截图基线测试。测试使用独立数据根与端口，不接管常驻开发服务；配置和夹具是具体路径与端口的事实来源。

`pnpm test:journey` 构建 Web/Server 后运行完整旅程；`pnpm verify:product` 执行完整交付检查。局部选择和构建复用方式见[检查阶梯](../../06-开发与测试规范.md#6-检查阶梯)，本文件不维护第二份命令清单。
